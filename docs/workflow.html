两份文本的比较阅读索引：从 PDF 到可检索笔记（分享版）

这是一份可以整套照做的工作流：把两篇作品（小说、戏剧、散文、诗集都行）从 PDF 变成 txt，再切成带摘要、引文和标签的段落索引，最后整理成写论文时真正用得上的“例证路线”。

适合：比较文学论文、IB 中文/英文 A、课堂报告、读书会、任何需要反复回到原文的写作。

不适合：只想随便读读、不需要引用原文的场景。那直接读原文就好。

0. 先看全貌

整套东西其实只有五步：

PDF
 ↓  转文字、清洗
txt（原文，不改）
 ↓  切段、写摘要、贴标签
分段索引（每段有段号、行号、摘要、引文、标签）
 ↓  自动校验 + 生成反查表
标签反查表 + 全文速查地图
 ↓  按论文论点挑段子
例证路线（写论文时先看这个）

如果你手里已经有可靠的 txt，可以直接从第 3 节开始；第 2 节是给只有 PDF 的人准备的。

最后你会得到这些文件：

my-project/
├─ README.md                 ← 给“下一次的自己/AI”看的工作说明
├─ INDEX.md                  ← 总导航
├─ 原文/
│  ├─ A.txt
│  └─ B.txt
├─ 索引/
│  ├─ index_A.md             ← A 的分段索引
│  ├─ index_B.md             ← B 的分段索引
│  ├─ tag_index.md           ← 标签反查表（自动生成）
│  └─ map.md                 ← 全文速查地图（自动生成）
├─ 例证路线.md                ← 按论点整理好的“最短证据链”
├─ 参考文献/
│  └─ ...
└─ tools.py                  ← 校验和生成用的小脚本（可选）

最重要的一条原则：

索引是地图，不是原文。 摘要只负责导航；引用一定回到 txt 逐字核对。

1. 建文件夹，先别急着读

建议一开始就把“原文”和“整理结果”分开：

my-project/
├─ 原文/          ← PDF 和转出来的 txt，尽量只读不改
├─ 索引/          ← 分段索引、标签表、地图
├─ 参考文献/      ← 论文、书评、背景资料
├─ README.md
└─ INDEX.md

文件名用你能一眼认出的名字，例如：

  • 日出.txt、太阳照常升起.txt
  • 或 textA.txt、textB.txt（如果你不想被作品名影响判断）

如果两篇文本版本不同，把版本写进文件名或 README：

  • 日出_1936初版.txt
  • 日出_1951修订版.txt
  • 太阳_赵静男译本_2011.txt

为什么要记版本？ 同一部作品不同版本，人物、台词、结尾都可能不一样。论文里要能说清“我依据的是哪一版”。

2. PDF 转 txt

2.1 先判断：文字版还是扫描版？

在终端里试一下：

pdftotext -layout 原文/A.pdf 原文/A_test.txt
wc -c 原文/A_test.txt
  • 如果 txt 有几万、几十万字节，打开能读到正常句子：多半是文字版。
  • 如果 txt 很小、几乎空白，或者全是乱码：多半是扫描版，需要 OCR。

也可以看 PDF 有没有嵌入字体：

pdffonts 原文/A.pdf

有字体列表，通常是文字版；没有，可能是扫描图片。

2.2 文字版：pdftotext

macOS 先装 poppler：

brew install poppler

Linux：

sudo apt install poppler-utils

Windows：下载 poppler for Windows，把 bin 加进 PATH。

转换命令：

pdftotext -layout -enc UTF-8 原文/A.pdf 原文/A_raw.txt

-layout 会尽量保留页面排版，适合有分栏、脚注、剧本格式的 PDF。如果转出来行被切得很碎，可以试试不加 -layout：

pdftotext -enc UTF-8 原文/A.pdf 原文/A_raw.txt

哪种读起来顺，就用哪种。不要两种混着用，否则行号会对不上。

2.3 扫描版：OCR

先装 OCRmyPDF 和中文语言包：

brew install ocrmypdf tesseract-lang
# 或 Linux: sudo apt install ocrmypdf tesseract-ocr tesseract-ocr-chi-sim

加一层文字，再转 txt：

ocrmypdf -l chi_sim+eng --deskew --clean 原文/A.pdf 原文/A_ocr.pdf
pdftotext -layout -enc UTF-8 原文/A_ocr.pdf 原文/A_raw.txt

英文书把 chi_sim+eng 换成 eng 即可。其他语言换成对应的 tesseract 语言代码。

如果 OCR 效果不好：

  • 先确认扫描分辨率够不够（一般 300 dpi 以上）。
  • 不要过度 --clean，有时会把细笔画弄掉。
  • 重要引文一定回 PDF 对照，OCR 错字很常见。

2.4 Python 备用方案

如果不想装命令行工具，可以用 PyMuPDF：

pip install pymupdf

import fitz  # PyMuPDF

pdf_path = "原文/A.pdf"
out_path = "原文/A_raw.txt"

doc = fitz.open(pdf_path)
with open(out_path, "w", encoding="utf-8") as f:
    for i, page in enumerate(doc, start=1):
        f.write(f"\n【第 {i} 页】\n\n")
        f.write(page.get_text("text"))
        f.write("\n")

这个脚本会把每页文字按顺序写出来，并保留页码标记。扫描版 PDF 用这个通常只能拿到空白或图片，还是得先 OCR。

2.5 清洗：保留结构，别把原文洗没了

转出来的 txt 通常有几类问题：

  1. 页眉页脚重复：书名、章节名、页码反复出现。
  2. 断行：一句话被切成好几行。
  3. 连字符：英文单词被拆成 under- / standing。
  4. 乱码/异体字：OCR 常见。
  5. 脚注混进正文：脚注编号和正文交错。

处理建议：

  • 用查找替换删掉重复页眉页脚，但保留页码标记（如 【第 12 页】），方便回查。
  • 段落之间保留空行；不要把整本书合成一大段。
  • 英文连字符断词可以合并，但先确认不是真正的连字符词。
  • 不要“顺手改写”原文句子。清洗只处理格式，不改内容。
  • 清洗前后各存一份：A_raw.txt（原始转换）和 A.txt（清洗后工作文本）。

清洗后做一次快速验收：

wc -l 原文/A.txt
head -40 原文/A.txt
tail -40 原文/A.txt
grep -n -E '第[一二三四五六七八九十]+章|CHAPTER|第[一二三四五六七八九十]+幕|ACT' 原文/A.txt | head -40

再搜一句你确定原文里有的句子，确认能搜到：

grep -n '一句你记得的原文' 原文/A.txt

如果章节标记不全、最后一页缺失、关键词搜不到，先别往下做索引。文本不完整，后面的索引全都会歪。

2.6 给原文加“页码/章节锚点”

建议保留两种锚点：

  • 页：【第 12 页】
  • 章/幕：第一章、第一幕、CHAPTER 1

这样索引里的行号之外，你还能说“第一幕”“第三章第二节”，即使别人用的版本页码不同，也能找到大致位置。

2.7 把行号/页码做成可点击的跳转

纯 .txt 没有 HTML 锚点，点 L123 不会自动滚动。最简单的做法是做一个小型原文阅读器：只保留一份 txt，用 JavaScript 在浏览器里生成行号，再用查询参数定位。

viewer.html?w=r&l=123      A 作品第 123 行
viewer.html?w=r&p=12       A 作品第 12 页
viewer.html?w=s&l=7418     B 作品第 7418 行
viewer.html?w=s&p=208      B 作品第 208 页

索引里写普通 Markdown 链接：

[L123](https://example.github.io/repo/viewer.html?w=r&l=123)
[第 12 页](https://example.github.io/repo/viewer.html?w=r&p=12)
[L7418–L7425](https://example.github.io/repo/viewer.html?w=s&l=7418)
[第 208 页](https://example.github.io/repo/viewer.html?w=s&p=208)
  • w=r / w=s 是两部作品的代号；只整理一部时可以省略。
  • l= 是行号，p= 是页码；行号链接指向起始行即可，跨行引文不用给每一行都做链接。
  • 页码链接指向该页第一行；没有页标记的 txt，先做一份“页码 → 起始行”的 TSV，再生成页码锚点。
  • 注意：引文内部的“第 14 页”不要加链接，否则会把原文引文改成导航文字。
  • 用完整的 HTTPS 链接（而不是本地文件 + #锚点）可以避开 Word / Markdown 预览丢 # 的问题。

阅读器的核心很小：fetch txt，按行生成 <div class="line" id="L123">，页面加载后按 ?l= 或 ?p= 滚动到对应元素。完整实现见本文件夹的 _build_site.py（生成站点）和 docs/assets/viewer.js（阅读器）。改完 txt 后重跑：

python3 _build_site.py

站点输出到 docs/，可以直接交给 GitHub Pages 托管。

3. 切段与贴标签

先提醒一句：不要跳过 PDF→txt，直接让 AI 读 PDF 来做索引。 PDF 的文字顺序经常是乱的，AI 很容易把页眉、脚注、分栏混在一起，甚至凭印象补出原文没有的句子。先把文字提出来，再让 AI 读 txt。

3.1 先定段号和粒度

不要按固定行数机械切。按场景、谈话回合、人物上下场、时间地点转换切。

  • 戏剧：一场戏、一次上下场、一个完整的谈话回合，大约 30–80 行。
  • 小说：一个场景、一次对话、一段行动，大约 40–100 行。
  • 诗歌：一节、一个完整的意象单元，可以更短。
  • 散文：一个自然段群或一个论述转折。

段号建议：

A1-01       A 的第一部/第一幕第 1 段
A2-03-02    A 的第二部第三章第 2 段
B-序-01     B 的序言/卷首第 1 段

规则越简单越好。后面的 session 只要看到 A1-01，就知道去 index_A.md 搜。

3.2 每段写什么

每段固定四行：

### A1-01｜L12–L48｜第一章：开场与人物登场
**内容**：2–4 句。谁在场、发生了什么、这段在结构上做什么。不要只写“两人交谈”。
**关键引文**：
- L20：“逐字引文，必要时用……省略。”
- L35：“第二句引文。”
**标签**：`主题标签` `人物标签` `写法标签` `用途标签`

几个硬要求：

  1. 摘要要具体：谁对谁说了什么、钱数、动作、道具、灯光、地点。不要写“表现了人物复杂的内心”这种空话。
  2. 引文必须逐字：从 txt 复制，不要凭记忆写。长引文只截关键 20–60 字，用 …… 表示省略。
  3. 每段 1–4 条引文：优先选能支撑论文的句子，不要把所有好句子都堆上去。
  4. 标签 3–7 个：至少一个主题标签；有形式特征就加写法标签；特别有用的段落加 核心例证。
  5. 不确定就多贴一个相关标签：宁可多看一眼，也不要漏掉关键例证。但不要把整张标签表都贴到一段上。

3.3 标签表：四组就够

不要一开始就发明几十个标签。先建四组，后面不够再加。

A. 主题/母题

太阳/天亮  光与暗  金钱/账单  阶级/贫富  劳动/工作
女性/被看  男性凝视  爱情/欲望  婚姻/贞操  性/身体
身体残缺/创伤  战争/战后  酒/醉酒  狂欢/节日  跳舞/娱乐
死亡/自杀  疾病/衰老  宗教/引文  道德/罪与罚  迷惘/虚无
逃避/麻木  孤独/无家  回忆/过去  自然/风景  钓鱼/野外
斗牛/暴力  城市/旅馆  旅行/流亡  希望/幻灭  命运/偶然
亲情/家庭  友谊  权力/控制  欺骗/谎言  同情/残忍  时间/日常

B. 人物

每个主要人物一个标签。次要人物只在真的反复出现时加。

C. 写法/形式

舞台说明  灯光  音响/鸡鸣  空间/屋内窗外  拉帐子  道具
服装/化妆  动作/表演  对白  独白/自言自语  沉默/停顿
旁白/评论  第一人称叙述  对话体  省略/留白  重复/回环
反讽  象征  引用/题词  结构对照  结尾/收束  开头/起笔
景物描写  细节/数字  节奏/长短句  不可靠叙述  视角/聚焦  互文

D. 用途

核心例证  次要例证  人物介绍  背景/过渡
对比点：A  对比点：B
论点A  论点B  论点C  论点D  论点E
备考引用

如果你写的是两部小说，就把 舞台说明、灯光、拉帐子 这类戏剧标签删掉；如果两部都是戏剧，就保留并加 出场/退场、观众所知。标签表要跟着文本类型改。

3.4 用 AI 批量做：一次处理一幕/一章

不要一次性把整本 7000 行丢给 AI 让它“全部整理”。分段质量会下降，而且很容易漏段。按幕/章切块，一次处理一块。

下面是一段可以直接改的 prompt：

你在为一篇比较文学论文建立文本索引。工作目录：<你的目录>

先读 <标签表文件名>，严格遵守其中的段号规则和标签表。标签必须从表里选，
不要自创。不要修改原文 txt。

任务：通读 <文件名> 的第 <起>–<止> 行，为全部内容建立分段索引。

要求：
1. 按场景/谈话回合/人物上下场/时间地点转换切分，不要机械按行数切。
   每段大约 30–80 行（小说可 40–100 行）；重要段落可更短。
2. 必须从 L<起> 连续覆盖到 L<止>，不留缺口、不重叠。
3. 段号用 <前缀>-01、<前缀>-02……按顺序编号。每章/每幕开头加一行
   `## 第X章（L起–L止）` 和一句本章概括。
4. 每段格式严格如下：

### <段号>｜L<起>–L<止>｜<短标题>
**内容**：2–4 句，写清谁在场、发生了什么、这段在结构上做什么。
**关键引文**：
- L<行号>：“<逐字引文>”
**标签**：`标签1` `标签2` `标签3` `标签4`

5. 标签每段 3–7 个。至少一个主题标签；有形式特征就加写法标签；
   对论文特别有用的段落加 `核心例证`。
6. 引文必须逐字准确，保留原文标点；长引文只截 20–60 字，用“……”省略。
   不要写你“记得”的句子，必须从原文复制。
7. 摘要要具体：谁对谁说了什么、钱数、动作、道具、灯光/声音变化。
8. 文件开头写覆盖范围和段号；文件结尾写「覆盖核对」表：
   段号 | 起止行 | 一句话内容；最后注明“连续覆盖，无缺口”。

用 write 工具把结果写入：<输出文件路径>
完成后只回复：文件路径、段数、覆盖行数、最重要的 5 个段号。

如果你用的 AI 支持子任务/并行，可以按幕/章拆成几个子任务同时做；最后合并成一个 index_A.md。合并时注意：

  • 每块的段号连续；
  • 不要重复章标题；
  • 合并后重新跑一次覆盖校验（见下一节）。

3.5 不要做的事

  • 不要把整段原文抄进索引。索引应该是“摘要 + 少量引文”，不是第二份全文。
  • 不要用 AI 的“记忆”写引文。AI 很会编看起来很像的句子。
  • 不要为了凑标签，把每段都贴成 核心例证。这个标签一多，就失去筛选作用。
  • 不要跳过卷首、目录、译者前言、注释。它们可能包含题词、版本信息、作者说明，写论文时很有用。

4. 校验：覆盖 + 引文

索引做完后，先别急着写论文。做两件事：

4.1 覆盖校验

检查：

  • 第一段是否从 L1（或你设定的起点）开始；
  • 最后一段是否到文件末；
  • 相邻段之间有没有缺口或重叠；
  • 有没有重复段号；
  • 有没有段落没有标签。

4.2 引文校验

把每条 - L123：“……” 的引文拿到原文对应行附近搜索。允许两种偏差：

  • 引文用 …… 省略了中间部分；
  • 引文跨了一两行。

如果搜不到，可能是：

  1. 引文不是逐字（AI 改写了）；
  2. 行号标错；
  3. 原文有 OCR 错字；
  4. 引文跨了多行，需要放宽搜索窗口。

4.3 一个通用小脚本

把下面存成 tools.py，放在项目根目录。先改最上面的 BOOKS 和 TAG_GROUPS，然后运行：

mkdir -p 索引
python3 tools.py check   # 校验覆盖、标签、引文
python3 tools.py tags    # 生成 tag_index.md
python3 tools.py map     # 生成 map.md

如果不想跑脚本，也可以把索引和原文交给 AI，让它逐段检查“有没有缺口、引文能不能在原文找到”。但 AI 会漏，重要项目还是建议跑一遍脚本。

SEG_RE = re.compile(r"^###\s+([^\s｜]+)｜L(\d+)[–\-]L?(\d+)｜(.+?)\s*$")
TAG_RE = re.compile(r"^\*\*标签\*\*[：:]\s*(.+)$")
QUOTE_RE = re.compile(r"^-\s*L(\d+)[：:]\s*(.+)$")
QUOTES = "“”‘’「」『』\"'《》〈〉"

def norm(s):
    s = re.sub(r"…+", "", s)
    s = re.sub(r"[\s" + QUOTES + "]", "", s)
    return s

def parse_index(path):
    segs, cur = [], None
    for line in open(path, encoding="utf-8"):
        line = line.rstrip("\n")
        m = SEG_RE.match(line)
        if m:
            if cur:
                segs.append(cur)
            cur = {"id": m.group(1), "start": int(m.group(2)), "end": int(m.group(3)),
                   "title": m.group(4), "tags": [], "quotes": []}
            continue
        if not cur:
            continue
        m = TAG_RE.match(line)
        if m:
            cur["tags"] = re.findall(r"`([^`]+)`", m.group(1))
            continue
        m = QUOTE_RE.match(line)
        if m:
            cur["quotes"].append((int(m.group(1)), m.group(2)))
    if cur:
        segs.append(cur)
    return segs

def check():
    allowed = {t for tags in TAG_GROUPS.values() for t in tags}
    all_errors = []
    for book in BOOKS:
        segs = parse_index(book["index"])
        src = open(book["src"], encoding="utf-8").read().splitlines()
        name = book["name"]
        print(f"\n[{name}] 段数：{len(segs)}")
        if not segs:
            all_errors.append(f"{name}: 没有解析到任何段")
            continue
        if segs[0]["start"] != book["start"]:
            all_errors.append(f"{name}: 首段起于 L{segs[0]['start']}，应为 L{book['start']}")
        if segs[-1]["end"] != book["end"]:
            all_errors.append(f"{name}: 末段止于 L{segs[-1]['end']}，应为 L{book['end']}")
        prev = None
        ids = set()
        for s in segs:
            if s["id"] in ids:
                all_errors.append(f"{s['id']}: 重复段号")
            ids.add(s["id"])
            if s["end"] < s["start"]:
                all_errors.append(f"{s['id']}: 起止行颠倒")
            if prev:
                if s["start"] == prev["end"] + 1:
                    pass
                elif s["start"] <= prev["end"]:
                    all_errors.append(f"{s['id']}: 与 {prev['id']} 重叠")
                else:
                    all_errors.append(
                        f"{s['id']}: 与 {prev['id']} 之间有缺口 "
                        f"L{prev['end'] + 1}–L{s['start'] - 1}")
            if not s["tags"]:
                all_errors.append(f"{s['id']}: 无标签")
            bad = [t for t in s["tags"] if t not in allowed]
            if bad:
                all_errors.append(f"{s['id']}: 未登记标签 {bad}")
            prev = s
        # 引文
        for s in segs:
            for lineno, quote in s["quotes"]:
                parts = [p for p in re.split(r"…+", quote) if norm(p)]
                window = norm("".join(src[max(0, lineno - 2):lineno + 2]))
                miss = [p for p in parts if norm(p) not in window]
                if miss:
                    window2 = norm("".join(src[max(0, lineno - 10):lineno + 9]))
                    miss2 = [p for p in parts if norm(p) not in window2]
                    if miss2:
                        all_errors.append(
                            f"{s['id']} L{lineno}: 引文找不到：{miss2[0][:30]}")
                    else:
                        all_errors.append(
                            f"{s['id']} L{lineno}: 引文不在标注行，但在前后 10 行内")
    print(f"\n错误：{len(all_errors)}")
    for e in all_errors:
        print("  ✗", e)
    return len(all_errors) == 0

def write_tags():
    by_tag = defaultdict(list)
    for book in BOOKS:
        for s in parse_index(book["index"]):
            for t in s["tags"]:
                by_tag[t].append((book["name"], s))
    out = ["# 标签反查表", "", "> 由 tools.py 自动生成。", ""]
    for gname, tags in TAG_GROUPS.items():
        out += [f"## {gname}", ""]
        for t in tags:
            items = by_tag.get(t, [])
            if not items:
                continue
            out.append(f"### `{t}`（{len(items)} 段）")
            for name, s in items:
                out.append(
                    f"- **{s['id']}** {s['title']}（{name}，L{s['start']}–L{s['end']}）")
            out.append("")
    open("索引/tag_index.md", "w", encoding="utf-8").write("\n".join(out))
    print("已生成 索引/tag_index.md")

def write_map():
    out = ["# 全文速查地图", "", "> 由 tools.py 自动生成。", ""]
    for book in BOOKS:
        out += [f"# {book['name']}", ""]
        for s in parse_index(book["index"]):
            out.append(
                f"- **{s['id']}**（L{s['start']}–L{s['end']}）{s['title']}  \n"
                f"  {' '.join('`' + t + '`' for t in s['tags'])}")
        out.append("")
    open("索引/map.md", "w", encoding="utf-8").write("\n".join(out))
    print("已生成 索引/map.md")

if __name__ == "__main__":
    cmd = sys.argv[1] if len(sys.argv) > 1 else "check"
    if cmd == "check":
        sys.exit(0 if check() else 1)
    elif cmd == "tags":
        write_tags()
    elif cmd == "map":
        write_map()
    else:
        print("用法：python3 tools.py [check|tags|map]")

这个脚本不完美，但能抓住最常见的错误：缺段、重叠、标签拼错、引文对不上。先把 BOOKS 里的路径和行号范围改成你的，再跑。

如果 check 报“未登记标签”，要么把标签改成表里已有的，要么把新标签补进 TAG_GROUPS；否则 tags 生成的反查表会漏掉它。

5. 回头做一份“例证路线”

索引是“按原文顺序”排的；写论文时你需要的是“按论点”排的。所以再做一个 例证路线.md。

5.1 先定三个可写的论点

不要写“两部作品都表达了……”。选一个具体问题：

  • 太阳升起时，人物在哪里、在做什么？
  • 钱怎样被说出来，或者被藏着？
  • 男人怎样看女人？谁在看，谁被看？
  • 热闹之后，人物得到了什么、失去了什么？
  • 作品怎样处理“看得见”和“被省略”的东西？

然后每个论点写一句话，必须能被文本证据支持，也必须允许反例。

5.2 每个论点排一条证据链

步骤 段号 原文写什么 可以怎么用
1 A1-04 具体场景、动作、台词 先让读者看到什么
2 A2-07 关键转折 这个细节怎样改变理解
3 B1-02 另一部作品的对应场景 两处放在一起比什么
4 B3-05 结尾/对照 比较后多知道了什么

每条链两边都要有证据。不要一边分析得很细，另一边只顺带提一句。

5.3 再列五个比较点

用一张表，把两篇作品在同一问题上的段号并排：

比较点 作品 A 作品 B 可说的差别
太阳/天亮 A4-09 B3-13 一个靠舞台空间，一个靠叙述语气
钱 A1-18 B1-04 一个被念出来，一个被藏起来
女人被看 A1-10 B1-03 一个多声部，一个单声道
酒/热闹 A2-28 B2-18 一个散场后没有家，一个散场后关系不在
形式 A3-02 B1-04 一个把“看不见”变成可听/可看，一个留在语言里

这张表就是你写比较段时的“骨架”。

5.4 再列一份关键引文表

# 引文 作品 段号 行号
1 “……” A A4-09 L1234
2 “……” B B3-13 L5678

引文不要多，10–20 条就够。每条都要能支撑一个具体论点，不要为了好看而收集“金句”。

6. 给下一次 session 写一份 README

你不可能每次都记得“上次做到哪、文件在哪、哪些引文核对过”。所以写一份 README.md，给下一次的自己或 AI 看。

最少写这些：

  1. 每次开始的阅读顺序：README → INDEX → 例证路线 → 分析规范 → 相关段号 → 原文。
  2. 文件夹里有什么：每个文件一句话。
  3. 索引怎么用：段号/行号、标签、核心例证 很宽、索引不是原文。
  4. 写作底线：先文本后解释、观点—证据—解释、区分文本/解读/推测、比较围绕问题、不把人物当作者、不诊断人物、不堆术语、引文逐字。
  5. 参考文献规范：先看阅读状态；只读摘要就标“据摘要”；不伪造页码/DOI/引文；区分版本和译本。
  6. 输出约定：新文件放哪、不要覆盖旧稿、不要改原文、新增分段后要重跑校验。
  7. 更新规则：用户提出要求时，后续 session 可以更新 README；只改必要部分；在 changelog 记日期、改动、原因。

一份 README 不需要很长。关键是让下一次 session 在五分钟内知道：这次该从哪里开始，什么不能做。

7. 写论文前的检查清单

  • [ ] 我知道这次是“找例证”“写分析”“比较”“找文献”还是“改文字”？
  • [ ] 我看过例证路线或标签反查表了吗？
  • [ ] 我读了分析规范里和这次任务相关的章节吗？
  • [ ] 我要用的引文，回原文逐字核对过吗？
  • [ ] 我分清文本事实、合理解读和推测了吗？
  • [ ] 我有没有把人物的话当成作者的观点？
  • [ ] 我有没有为了显得深刻而堆术语？
  • [ ] 如果用了文献，我标了阅读状态和出处吗？
  • [ ] 我的比较是不是围绕一个问题，而不是两篇简介？
  • [ ] 我有没有说出“比较后多知道了什么”？

8. 常见坑

  1. PDF 转出来顺序错乱：分栏、脚注、页眉页脚都会干扰。先读几页确认顺序，再开始切段。
  2. OCR 错字被当成原文：尤其是人名、数字、标点。重要引文回 PDF 对照。
  3. 行号漂移：你后来重新转了一次 PDF，行号全变了。索引里的行号要重跑校验；不要凭旧行号引用。
  4. 引文是 AI 改写的：看起来很像，但不是原文。每条引文都要能 grep 到。
  5. 标签爆炸：一段贴十几个标签，反查表就失去意义。每段 3–7 个，核心例证 少用。
  6. 只整理一部作品：比较论文需要两边的证据。每一条论点都要问“另一部呢？”
  7. 把摘要当论文句子：摘要只是导航。论文里的每个判断都要有原文支撑。
  8. 把作者、叙述者、人物混为一谈：方达生说的不是曹禺说的，杰克说的不是海明威说的。
  9. 用文献代替文本：二手资料可以支持/对照，但不能代替你对具体场景的分析。
  10. 没有版本信息：不同版本的人物、台词、结尾可能不同。论文里要写清依据哪一版、哪一译本。

9. 一页流程总结

1. 建文件夹：原文 / 索引 / 参考文献
2. PDF → txt：pdftotext 或 OCR；保留页码/章节锚点
3. 验收：行数、首尾、章节标记、关键词能搜到
4. 按幕/章切块，用 AI 或手动写分段索引
   每段：段号｜行号｜标题｜摘要｜引文｜标签
5. 校验：覆盖无缺口、引文逐字、标签合法
6. 生成：标签反查表 + 全文速查地图
7. 按论点整理：例证路线（3 条论点 + 5 个比较点 + 关键引文表）
8. 写 README：阅读顺序、文件地图、写作底线、更新规则
9. 写论文：先看例证路线，再回原文核对引文
